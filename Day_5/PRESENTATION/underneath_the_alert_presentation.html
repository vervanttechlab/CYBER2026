What Runs on a Machine — and Where It Should Live

PROCESSES — running programs.
Get-Process
SERVICES — background programs, often from boot.
Get-Service
SCHEDULED TASKS — jobs set to run at a time or event.
Get-ScheduledTask
STARTUP / AUTORUNS — programs that start by themselves.
Autoruns
File Lives in
svchost.exe / lsass.exe C:\Windows\System32
explorer.exe C:\Windows

A name can be faked in seconds. A location is harder. On Day 3, svhost32.exe in C:\Users\Public was a red flag BEFORE we looked anything up — wrong name, wrong place.

You cannot spot the strange until you know the normal. Services and scheduled tasks are favourite hiding places, because both survive a reboot. (Note: macOS and Ubuntu do the same jobs with different commands.)

What is a baseline?

A snapshot of a healthy machine, taken now, so that later — when something new appears — you have something to compare against.

A copy you have not checked is not a backup. It is a hope. Hash it, copy it, hash the copy, compare.

On Day 3, "port 443" told us the traffic was encrypted — that is WHY the address was all we could read.

A private address is inside the building; the internet cannot reach it directly. NAT is the translation the router does so many private devices share one public address.

Slide 6

The Command That Finishes the WKS-311 Ticket

Find the PID of the connection:

netstat -ano | findstr ESTABLISHED

Turn the PID into a name:

tasklist /fi "pid eq 6820"

Do it all in one PowerShell line:

Get-NetTCPConnection -State Established | Select LocalPort, RemoteAddress, RemotePort, @{n='Process';e={(Get-Process -Id $_.OwningProcess).ProcessName}}
svhost32.exe

Address, port, AND the program that owns the connection — in one line. Run this on WKS-311 and you get svhost32.exe. That is the process we could not name on Day 3.

Slide 8

One Machine You Are Allowed to Scan: Your Own

NAT

Many private devices share one public address going out. Automatic and safe.

PORT FORWARDING

A hole made on purpose, sending one public port to one inside machine. It is how inside servers get exposed. A network review looks here first.

ROUTER

Out (NAT) ➔
⬅ In (Port Fwd)
127.0.0.1 ONLY

Scanning any machine that is not yours, without written permission, is illegal under RA 10175, the Cybercrime Prevention Act. Today we scan only 127.0.0.1 — this machine.

The full lab-subnet scan needs the real lab and a signed permission. It waits for our first day on site.

Slide 9

One Request, and What the Server Wrote Down

BROWSER ➔ DNS ➔ [ WAF / proxy ] ➔ WEB SERVER ➔ APPLICATION ➔ back
203.0.113.45 - - [.../09:20:11] "POST /wp-login.php HTTP/1.1" 200 6712 "-" "python-requests"
who | when | method+path | result | size | the tool
Code Meaning
200 OK served it (NOT the same as "fine")
302 redirect after login often = success
403 forbidden blocked, often the WAF
404 not found a BURST from one address = a scanner

The most dangerous line in a log is often a 200, not a 403. A 200 means it WORKED.

Slide 10

Activity 3 — Tell the Story in the Log

  • Your team gets 40 lines of a website's log. Six addresses appear.
  • For each address: is it a normal visitor, a scanner, or the attacker? Give one line of proof.
  • Put the attack in order, using the timestamps.
  • Then: which single line is the WORST thing in the log? And is this THREAT, DETECTION, or ROUTER?
Visitor Scanner Attacker

The blocked attacks (403) are the noise. Look for the request that SUCCEEDED (200). That is the fire.

Slide 11

A Script Is Just Instructions You Can Read

A good script (today's parser):

  • opens a file
  • matches each line
  • counts status codes and addresses
  • prints

It touches nothing and sends nothing out.

What a bad script does:

  • reaches out to the internet to fetch more code
  • hides itself with encoding
  • runs whatever it fetched

Read a suspicious script. NEVER run it. Running it is the incident. Reading it is enough to escalate.

"It ran fine and found nothing" is not "there is nothing." Scripts have bugs. Check the silence.

Slide 12

Activity 4 — Read Three Scripts. Run None.

  • In pairs, read three short scripts.
  • For each: What does it do? Does it touch the internet? Would you RUN it, or ESCALATE it?
  • You will not run any of them. Reading is the job.

One is safe. One fetches and runs code from the internet — escalate it. One has a bug and reports zero problems in a log full of them.
